# 运维与恢复

## 备份

停止服务后，复制 `data/workbench.sqlite`、`data/workbench.sqlite-wal`（若存在）和 `logs/` 到受保护的备份位置。为了得到一致快照，推荐先用前台服务按 `Ctrl+C` 停止，再复制文件。

商务资源、销售机会、合作项目、活动、跟进和 AI 草稿均保存在同一个 SQLite 数据库中，不需要额外备份目录。AI 草稿可能包含用户主动粘贴的原始沟通内容；创建草稿前应避免提交密码、密钥和无关敏感信息。

## 恢复

1. 停止服务。
2. 将备份文件恢复到 `data/`，保留同一目录结构。
3. 执行 `pnpm migrate`。
4. 执行 `pnpm start:server` 和 `pnpm dev -- --port 5173`，再打开 <http://127.0.0.1:5173/>。

Skill 删除是可恢复操作：目录会进入 Windows 回收站。恢复前先在 Skill 管理中确认目录位置，并避免在工作台重新生成同名目录。

## 故障排查

- 页面打不开：确认 5173 端口服务已启动，再检查 API 4310 是否运行。
- 首页显示缓存：这是 Codex App Server 暂时不可用时的只读降级；不要把缓存当成实时 Skill 列表。
- 任务失败：在任务详情查看错误码、错误消息和完整日志；可使用“重试”。
- 服务异常退出：启动时会把仍处于 running 的运行记录标记为 `SERVICE_INTERRUPTED`，避免显示为永久运行。
- 端口冲突：修改 `WORKBENCH_PORT` 或前端端口，并同步 `WORKBENCH_UI_API_PORT`（仅在前端代理到非默认 API 端口时需要）。
- 商务 AI 不可用：检查 Codex 登录和 SDK 能力。手动商务管理仍可使用，未确认的 AI 草稿不会修改正式数据。

## 交付验收清单

- [ ] `pnpm check` 全部通过。
- [ ] 启动后可访问 `http://127.0.0.1:5173/`。
- [ ] 任务可创建、立即运行、失败重试、暂停、软删除和恢复。
- [ ] Skill 可列出、查看详情和启停；系统 Skill 不显示删除按钮。
- [ ] 商务模块可建立公司、联系人、机会、合作、活动和跟进，并能推进业务状态。
- [ ] AI 整理只生成草稿，确认后才创建活动与跟进；AI 不可用时手动录入正常。
- [ ] Codex 不可用时页面明确显示缓存状态，且不执行删除等写操作。
- [ ] 备份与回收站恢复路径已实际演练。
