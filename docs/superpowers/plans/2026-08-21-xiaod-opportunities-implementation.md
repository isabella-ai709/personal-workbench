# “小D机会”跨仓库实施计划

## 目标与边界

- `ai-weekly` 一次采集后生成原 AI 周报和独立的小D机会周报。
- `personal-workbench` 在“AI新闻资讯”下新增“小D机会”子频道。
- 原 AI 周报来源、筛选、契约、页面和发布行为保持不变。
- 首期接入36氪官方文章与快讯 RSS，不接入机器之心。
- 保留用户在 `personal-workbench/scripts/start-local.ps1` 和 `src/client/styles/tokens.css` 的未提交改动。

## 检查点 1：联合采集与来源作用域

**仓库：** `ai-weekly`

1. 为 `SourceConfig` 增加 `scopes`，现有来源默认同时服务两个分支，新来源只服务小D。
2. 增加36氪文章、快讯和已确认官方来源配置；无法返回标准 Feed 的来源记录错误而不进入默认成功集合。
3. 将采集结果按来源保存；每个来源每次运行只调用一次采集器。
4. 原 AI 分支从现有来源 ID 构建输入，保证新增来源不改变原统计和候选。

**验证：** 来源调用计数、分支输入隔离、Feed 内容类型/根节点、防拦截页测试。

## 检查点 2：小D领域模型与确定性过滤

**仓库：** `ai-weekly`

1. 新增小D报告、雷达、案例、销售素材、副业和排序模型。
2. 实现全字段、不区分大小写的必追词与屏蔽词匹配。
3. 实现必追词优先和 LoRA 自动化营销例外。
4. 实现三个行业相关度、行动性、证据完整度、难度和离钱距离判断。
5. 缺少成本、周期或 ROI 时使用 `undisclosed`，禁止生成数字。

**验证：** 关键词冲突、空字段、LoRA、行业过滤、事实状态和唯一推荐规则测试。

## 检查点 3：六段式报告与双发布

**仓库：** `ai-weekly`

1. 构建六段式 JSON、Markdown 和 HTML。
2. 无 LLM 时使用保守模板并允许空栏目。
3. 独立写入 `YYYY-WXX-xiaod-opportunities.*`。
4. 增加小D工作台发布器；两个发布结果和异常互不影响。
5. 在同一个计划任务中执行两个分支，不新增计划任务。

**验证：** 本地文件、无 LLM、分支失败隔离、发布失败隔离和历史快照测试。

## 检查点 4：工作台契约、存储和接口

**仓库：** `personal-workbench`

1. 新增小D Zod 契约和 TypeScript 类型，不修改 `AiNewsReport`。
2. 新增 `ai_opportunity_reports` 迁移、Repository、Service 和 Routes。
3. 新增幂等机器写入与列表、最新、详情接口。
4. 精确扩展 Bearer Token 机器路由安全判断。
5. 小D报告成功写入时生成幂等消息提醒。

**验证：** 契约、迁移、幂等、认证、错误状态和原 AI API 回归测试。

## 检查点 5：子频道页面

**仓库：** `personal-workbench`

1. 增加 `/ai-news/opportunities` 懒加载路由。
2. 将“小D机会”以缩进子项显示在“AI新闻资讯”下。
3. 新增独立 API 客户端、页面、六段式阅读器和样式文件。
4. 支持历史周次、刷新、加载、错误和空状态。
5. 用 React 节点安全渲染必追词高亮，不插入原始 HTML。

**验证：** 组件测试、路由和导航测试、键盘可用性、窄屏布局和原 AI 页面回归。

## 最终验证与交付

1. `ai-weekly`：运行完整 pytest 和一次可用网络条件下的真实最近7天采集。
2. `personal-workbench`：运行相关测试、完整测试、类型检查、lint 和构建。
3. 检查两个仓库 diff、Secret、原频道行为和用户已有未提交修改。
4. 分仓库提交清晰检查点，报告未完成项和外部来源限制。
