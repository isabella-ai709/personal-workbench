# 消息提醒中心实施计划

## 约束

- 以已确认的 `2026-08-20-message-center-design.md` 为准。
- 不覆盖 `src/client/styles/tokens.css` 中已有的用户修改；消息中心样式放入独立文件。
- 首版只实现站内消息，不接外部推送。

## Task 1：数据库与共享契约

1. 新增迁移，扩展任务计划 `cancelled` 状态并创建 `notifications` 表及查询索引。
2. 新增消息级别、状态、来源、筛选、稍后提醒和快捷动作契约。
3. 更新任务计划状态契约、分组规则和现有状态展示。
4. 更新迁移测试与契约测试。

## Task 2：消息仓储、扫描和服务

1. 实现消息幂等发布、分页查询、摘要统计和状态更新仓储。
2. 实现按 Asia/Shanghai 自然日计算的提醒扫描：任务计划 3 天，商务合作和跟进 7 天，1 天内升级紧急。
3. 实现稍后提醒恢复、来源失效关闭和截止日期版本去重。
4. 实现消息服务与来源动作适配，所有业务变更走现有服务层。
5. 注册消息 API，并在列表与摘要读取前执行扫描。

## Task 3：来源接入

1. AI 周报写入事务中幂等创建普通消息。
2. 任务计划支持取消状态、推进、延期和取消动作。
3. 商务合作支持状态推进选择、延期和终止；商务跟进支持完成、改期和取消。
4. 确保来源变更与消息处理一致，失败时不留下假处理状态。

## Task 4：客户端

1. 新增消息 API 客户端和 React Query 数据流。
2. 新增消息中心页面、筛选、卡片、状态操作、稍后提醒和来源动作。
3. 在首页之后增加导航入口和重要未读红点。
4. 使用独立 `notifications.css` 完成桌面和窄屏布局。

## Task 5：验证

1. 单元测试覆盖提醒窗口、升级、状态转换和去重。
2. 集成测试覆盖扫描、AI 新闻通知、API 与来源动作。
3. 组件测试覆盖普通、重要、紧急消息及用户操作。
4. 运行 `pnpm check`、`pnpm test:integration` 和生产构建。
5. 通过浏览器验证导航、红点、筛选和响应式布局。
