# 小D机会整页 UI 升级设计

## 1. 目标与范围

本次改版覆盖 `/ai-news/opportunities` 的页头、报告正文、加载、空数据和错误状态。目标是把当前由相似白色卡片组成的周报页升级为可快速扫读、突出行动优先级的“商业情报编辑台”。

保留现有路由、导航名称、API、报告字段、周次切换、刷新行为、来源链接和内容文案。不得修改原“AI新闻资讯”页面，也不得改动当前已有用户修改的 `src/client/styles/tokens.css`。

## 2. 设计判断

这是面向私域运营者的工作台内页，不是营销落地页。`design-taste-frontend` 用于视觉审计、版式语言和反模板化约束；交互控件继续使用项目现有的 Fluent UI，避免引入第二套设计系统。

采用“商业情报编辑台”方向：冷灰背景、深墨色正文、焦橙色作为页面内唯一强调色。视觉升级属于保留型改版，不改变信息架构和用户操作习惯。

设计参数：

- `DESIGN_VARIANCE: 5`：使用适度非对称布局，加强主次关系。
- `MOTION_INTENSITY: 3`：只使用悬停、按压和状态反馈，不加入自动动画。
- `VISUAL_DENSITY: 5`：适合工作台的中等密度，保证长周报可扫读。
- 页面锁定浅色主题，不在单个区块中切换深色主题。
- 卡片统一使用 12px 圆角；按钮和输入控件使用 8px 圆角。

## 3. 当前问题与保留项

### 3.1 当前问题

- 页头左侧文案和右侧控件相距过远，周次选择与报告内容缺少关系。
- 标题、状态条和首要判断之间层级重复，首屏没有明确告诉用户本周应该先看什么。
- 正文区块几乎都使用相同的白色卡片和网格，商业判断、销售素材和副业排序难以区分。
- 深色渐变判断卡与浅色页面形成一次不必要的主题翻转。
- 加载态只显示一行文字，空状态和错误态没有延续页面结构。
- 宽屏空间利用率低，移动端布局规则不够明确。

### 3.2 必须保留

- `/ai-news/opportunities` 路由和左侧导航结构。
- “小D机会”、六个周报栏目名称和现有正文内容。
- 历史周次选择、刷新数据、原始来源链接及其键盘可用性。
- React Query 数据获取与现有加载、错误、空数据逻辑。
- 当前页面使用的 Fluent UI Button 和 MessageBar。

## 4. 页面结构

### 4.1 情报页头

页头使用两列非对称网格。左侧依次显示频道归属、页面标题和一句价值说明；右侧为独立操作台，包含可见的“周报期次”标签、周次选择器和“刷新数据”按钮。

操作台在视觉上与标题保持同一基线，不悬浮到页面最右侧。桌面端控件同排，低于 768px 时堆叠为单列。选择器保留原生 `select`，增加明确的焦点样式和足够点击高度。

现有同步状态放在页头下方，改成一条真实数据摘要，展示报告日期、来源数和机会数。状态信息来自当前报告，不增加装饰性状态点或虚构指标。

### 4.2 本周搞钱判断

首要判断改为浅色的编辑式结论区，不使用深色渐变。焦橙色仅用于左侧强调边和小范围关键提示。标题承担主要视觉重量，摘要保持适合阅读的行宽。

该区域的职责是回答“本周先做什么”，因此在报告正文中保持最高优先级，但不增加新的业务字段或行动按钮。

### 4.3 行业机会雷达

雷达条目使用响应式两列网格。每条机会由标题、行业、事件描述、商业判断和行动信息组成。内部通过间距和少量分隔线建立层级，不为每个字段再套一层卡片。

必追词继续使用安全的结构化 `<b>` 高亮，焦橙色只用于命中词和可执行动作。原始来源链接保持清晰且可聚焦。

### 4.4 落地案例

案例使用纵向列表而不是重复雷达卡片。标题、场景、付费方和风险形成稳定的两级结构，使用户可以沿页面快速比较案例。

### 4.5 本周销售素材

销售素材使用一个结构化面板，朋友圈、私聊和跟进分别成为三个清晰的内容块。桌面端采用不等宽布局，优先突出私聊和跟进；移动端改为单列。首期不新增复制按钮，避免扩大功能范围。

### 4.6 副业灵感池

副业机会保留卡片结构，但减少装饰。行业、难度和离钱距离形成紧凑元数据区，准备素材和执行步骤作为正文，不使用评分进度条。

### 4.7 本周副业优先排序

排序区分为“唯一推荐”和“其余排序”两个层级。满足规则的推荐项使用焦橙色边框与浅色底，其余 TOP 项使用简洁编号列表。没有合格推荐时继续使用 Fluent MessageBar，并明确说明不强行推荐。

## 5. 状态设计

### 5.1 加载

加载态显示与最终布局相近的静态骨架，包括页头、状态摘要和两个正文块。骨架不使用持续闪烁动画，避免无意义运动并兼容减少动态效果偏好。

### 5.2 空数据

保留“还没有小D机会周报”的事实说明，在完整页头下显示一个有边界的空状态。文字说明首次自动推送后将出现内容，不提供当前系统无法执行的按钮。

### 5.3 错误

错误态保留 MessageBar 和“重新加载”操作，同时显示页面标题，避免错误发生时整页结构消失。重新加载继续同时刷新报告列表和当前报告。

## 6. 响应式与可访问性

- 页面主体保持现有最大宽度体系，不修改全局布局变量。
- 低于 768px 时，页头、操作台、雷达网格和销售素材全部切换为单列。
- 标题使用 `clamp()` 控制尺寸，避免窄屏换行失控。
- 所有正文维持可读行高，长链接可正常换行。
- 选择器使用可见标签，不使用占位文本代替标签。
- Button、select 和链接提供清晰的 `:focus-visible` 状态。
- 按钮文字不换行，文字与背景对比满足 WCAG AA。
- 页面不新增外部字体、图片、动画库或图标库。

## 7. 实现边界

主要修改：

- `src/client/pages/ai-opportunities-page.tsx`
- `src/client/styles/ai-opportunities.css`

如需验证渲染状态，可新增或扩展小D页面组件测试。不得修改 API、服务端契约、数据库、抓取逻辑或原 AI 新闻页面。不得覆盖 `scripts/start-local.ps1` 和 `src/client/styles/tokens.css` 中已有的用户改动。

## 8. 验证与完成标准

### 8.1 自动验证

- TypeScript 类型检查通过。
- 相关组件测试和现有测试通过。
- ESLint 与 Prettier 检查通过。
- Vite 生产构建通过。

### 8.2 视觉验证

在桌面宽屏和小于 768px 的移动宽度分别检查：

- 页头、操作台和正文首屏层级清晰。
- 报告六个栏目具有不同但一致的呈现结构。
- 页面只使用一个焦橙强调色，没有 AI 紫色、霓虹发光和无意义渐变。
- 圆角规则、焦点样式、按钮对比和文本换行一致。
- 加载、空数据、错误和成功状态均保持完整页面结构。
- 页面可见文案不包含破折号式装饰、虚构数据或新增业务结论。

### 8.3 完成定义

用户在进入页面后的首屏内可以立即识别当前周次、同步范围、本周核心判断和刷新入口；继续向下阅读时，可以通过不同布局快速区分机会、案例、销售素材和副业排序，同时现有功能与数据行为保持不变。
