# 个人 Codex 工作台设计规格

- 日期：2026-08-17
- 状态：用户已确认设计，等待书面规格复核
- 第一版范围：工作台任务日志、Codex Skill 管理
- 运行方式：仅本机访问的网页应用

## 1. 背景与目标

用户希望建立一个面向个人生活与部分工作的统一工作台，最终承担 Skill 管理、API 管理、任务日志、商务对接和经验复盘等职责。为控制第一版复杂度，本规格只设计两个核心模块：任务日志和 Skill 管理。

第一版的目标是：

1. 在一个本机网页中查看和管理工作台拥有的定时任务。
2. 查看 Codex 能发现的 Skills，并安全完成启用、停用、查看和受限删除。
3. 展示真实状态和运行结果，不使用静态登记冒充系统状态。
4. 为后续 API 管理、商务对接和经验复盘保留清晰的模块边界。

成功标准不是“做出一个仪表盘页面”，而是用户能够在日常使用中快速回答：今天有哪些任务、哪些失败了、结果是什么、当前有哪些 Skills、它们来自哪里、是否启用。

## 2. 已确认的关键决策

### 2.1 本机优先

第一版由浏览器界面和本地服务组成，只监听 `localhost`。不开放局域网或公网访问，也不承诺第一版支持手机。

### 2.2 工作台任务与原生 Scheduled Tasks 分离

官方文档说明 ChatGPT/Codex 桌面端和网页可以创建及管理 Scheduled Tasks，但公开的 Codex App Server 协议没有列出 Scheduled Tasks 的查询、启停或删除方法。因此第一版不能承诺直接管理已有的原生 Scheduled Tasks。

工作台建立自己的调度器，并使用 Codex SDK 执行任务。工作台只管理自己创建或迁移进来的任务。已有原生 Scheduled Tasks 继续留在 Codex 中，由用户手动管理或逐项迁移。界面必须明确标注这一边界，不能把原生任务显示成可管理对象。

### 2.3 Skill 使用公开能力

Skill 清单和启停优先通过 Codex App Server 的公开方法完成：

- `skills/list`：获取可发现 Skills 及其状态。
- `skills/config/write`：按路径启用或停用 Skill。
- `skills/changed`：收到文件变化通知后刷新清单。

禁止为了实现功能而直接修改 Codex 未公开的内部数据库或私有任务存储。

### 2.4 删除必须可恢复

任务采用软删除，保留 30 天。可删除的本地 Skill 先停用，再移入操作系统回收站。系统 Skill 和插件自带 Skill 为只读，不提供删除操作。

## 3. 非目标

第一版不包含：

- 直接管理 Codex 原生 Scheduled Tasks。
- 云端部署、手机访问或多用户协作。
- API 凭证管理。
- 商务关系管理和经验复盘内容库。
- 在线 Skill 市场、安装、自动升级和版本依赖修复。
- 在网页中创建或编辑完整 Skill 内容。
- 复杂的任务编排、并行工作流或分布式执行。

## 4. 总体架构

系统分为四个边界明确的单元。

### 4.1 浏览器界面

提供今日总览、任务日志和 Skill 管理三个页面。浏览器只调用本地服务定义的业务接口，不直接访问任意本机文件，也不直接启动 Codex 进程。

### 4.2 本地工作台服务

负责输入校验、操作确认、权限限制、数据读写、状态推送和错误转换。它是浏览器与 Codex 能力之间的唯一入口。

### 4.3 任务引擎

包含本地调度器和 Codex SDK 执行适配器。调度器决定何时运行，SDK 适配器负责实际执行。两者通过稳定的任务请求和运行结果对象通信，便于独立测试或未来替换执行方式。

### 4.4 Skill 适配器

通过 Codex App Server 获取清单和执行启停。来源分类由 App Server 信息、路径范围和工作台本地来源记录共同决定。适配器不可用时，Skill 页面降级为缓存只读模式。

### 4.5 本地数据存储

SQLite 保存工作台业务数据，包括任务、计划、运行记录、Skill 人工来源标记和界面设置。完整大日志保存为本地日志文件，SQLite 只保存索引、摘要和文件位置。Skill 正文仍保留在原目录，不复制第二份。

## 5. 页面设计

### 5.1 今日总览

首页显示：

- 今日待运行任务数。
- 成功、失败、暂停和未查看结果数量。
- Skill 总数、已启用数和自建数。
- 最近任务运行记录。
- 失败或需要关注的结果。
- 新建任务、查看失败结果、刷新 Skills 等快捷操作。

侧边栏预留 API 管理、商务对接和经验复盘入口，但第一版显示为未启用，避免让用户误以为这些模块已经可用。

### 5.2 任务日志

采用“任务列表 + 选中结果同屏”的结构。

任务列表显示名称、简述、运行计划、状态、最近运行和常用操作。支持全部、运行中、已暂停、失败筛选以及名称搜索。

主要操作包括：

- 启用或暂停。
- 立即运行。
- 查看最近结果和完整日志。
- 修改任务。
- 对失败任务重新运行。
- 软删除和恢复。

删除前必须二次确认。立即运行按钮在提交后进入不可重复点击状态；服务端还需使用幂等键和任务锁，不能只依赖按钮禁用。

### 5.3 Skill 管理

采用“Skill 清单 + 详情同屏”的结构。

清单显示名称、简述、来源分类和启用状态。支持按自建、已安装、系统、插件筛选，也支持名称或说明搜索。

详情显示：

- 名称和说明。
- 来源分类与作用范围。
- 启用状态。
- 路径和更新时间。
- 可用的界面元数据与依赖信息。

主要操作包括查看 `SKILL.md`、打开目录、启用、停用和人工标记来源。只有自建和普通用户 Skill 可以移入回收站。系统和插件 Skill 不显示删除操作。

## 6. Skill 来源分类规则

“自建”和“已安装”不是 Skill 标准结构中的强制字段，不能仅凭 `SKILL.md` 准确判断。分类规则如下：

1. 系统范围的 Skill 标记为“系统”。
2. 明确由插件提供的 Skill 标记为“插件”。
3. 由工作台或 Skill 创建流程登记过的 Skill 标记为“自建”。
4. 用户范围内、具有安装记录但没有自建记录的 Skill 标记为“已安装”。
5. 其他旧的用户级 Skill 标记为“待确认”，由用户选择“自建”或“已安装”。

人工分类记录只影响工作台展示，不修改 Skill 的标准内容。重新扫描时保留人工标记，除非路径已经不存在。

## 7. 任务模型与状态

任务定义至少包含：

- 标识、名称、说明。
- 执行提示或工作流定义。
- 运行计划和时区。
- 启用状态。
- 工作目录。
- 需要调用的 Skills。
- 文件、网络和其他权限要求。
- 创建、修改和软删除时间。

运行记录至少包含：

- 任务标识和运行标识。
- 触发类型：计划运行或手动运行。
- 计划时间、开始时间、结束时间和耗时。
- 状态、结果摘要和完整日志位置。
- 结构化错误类型和可读错误信息。

状态转换为：

`等待运行 → 运行中 → 成功 / 失败 / 已取消 / 已错过`

第一版同一时间只执行一个任务。同一任务已有运行实例时，新的立即运行请求返回“任务正在运行”，不能创建重复实例。

## 8. 调度规则

- 所有计划显式保存时区，第一版默认为 `Asia/Shanghai`。
- 电脑关闭期间错过的任务记录为“已错过”，启动后不集中补跑。
- 默认不自动重试，防止重复发送消息、重复写文件或重复调用外部服务。
- 用户可以从失败结果中手动重新运行。
- 服务重启后重建未来计划，但不得重复执行已经领取过的运行记录。
- 调度器领取任务和创建运行记录必须在同一事务或等价的原子操作中完成。

## 9. 数据保留与删除

- 普通运行记录默认保留 90 天。
- 被软删除的任务保留 30 天后清理。
- Skill 删除优先使用操作系统回收站，不执行不可恢复的递归删除。
- 清理策略可以在设置中修改，但不属于第一版首页功能。
- 数据库、日志和备份目录不得提交到版本控制。

## 10. 异常处理

### 10.1 App Server 不可用

显示最近一次成功获取的 Skill 清单，并清楚标记“只读缓存”。隐藏或禁用启停操作，提供重试入口。不得把缓存状态冒充实时状态。

### 10.2 Skill 变更失败

只有 App Server 返回成功并重新读取状态后，界面才显示最终成功。失败时保持原状态并展示可读原因。

### 10.3 SDK 执行失败

必须创建失败运行记录，保留错误类别和日志。第一版不自动重试。错误信息不得泄露密钥。

### 10.4 服务异常退出

重启时检查处于“运行中”但没有存活执行进程的记录，将其转为失败并注明“服务中断”，然后恢复未来调度。

### 10.5 删除失败

删除过程未完整成功时，原对象继续显示。不得先从界面永久隐藏、再异步尝试不可恢复删除。

## 11. 安全设计

- HTTP 服务默认只绑定 `127.0.0.1` 或等价的本机回环地址。
- 本地会话使用随机令牌，修改操作需要防跨站请求保护。
- 浏览器提交的文件路径必须与服务端允许的根目录进行解析后校验。
- 任务按最小权限运行；网络和扩大文件访问必须显式配置。
- 系统及插件 Skills 保持只读。
- 敏感凭证不写入 SQLite、任务日志或普通配置文件；未来使用环境变量或操作系统凭证库。
- 日志展示和持久化前对已识别的令牌、密钥和认证头进行遮蔽。
- 破坏性操作必须有明确目标、二次确认和可恢复路径。

## 12. 技术验证关卡

正式开发前先完成一个最小能力验证：

1. 在当前 Windows 环境启动 Codex App Server。
2. 调用 `skills/list` 并取得当前环境的真实 Skill 清单。
3. 对一个可安全测试的用户 Skill 调用 `skills/config/write`，验证停用和恢复启用。
4. 验证 `skills/changed` 或强制刷新后的状态一致。
5. 使用 Codex SDK 运行一个无外部副作用的测试任务，并取得可归档的结果。

任何验证失败都要记录为兼容性问题并调整设计。不得通过编辑未公开内部数据库绕过失败。

## 13. 测试策略

### 13.1 单元测试

- 计划解析、时区和下一次运行计算。
- 状态转换和非法转换拒绝。
- 来源分类优先级。
- 日志脱敏。
- 路径范围校验。
- 软删除和保留期计算。

### 13.2 集成测试

- App Server 的 Skill 列表、启停和刷新。
- Codex SDK 执行成功、失败和取消。
- SQLite 事务、任务锁和服务重启恢复。
- 回收站移动失败时的数据一致性。

### 13.3 端到端测试

- 创建任务、立即运行、查看结果。
- 暂停任务后不再触发，恢复后重新调度。
- 连续点击立即运行不会产生重复实例。
- 删除并恢复任务。
- App Server 下线时 Skill 页面进入只读缓存状态。
- 系统及插件 Skill 不出现删除按钮。

## 14. 验收标准

1. 能列出当前 Codex 可发现的 Skills，并显示启用状态。
2. Skill 启停后重新读取，状态仍然正确。
3. 系统及插件 Skill 无法从工作台删除。
4. 能创建、暂停、恢复、立即运行和软删除工作台任务。
5. 任务按计划运行，并保存结果或明确错误。
6. 重复点击不会产生重复运行。
7. 服务重启后任务定义、未来计划和历史记录不丢失。
8. 删除的任务在 30 天内可以恢复。
9. App Server 或 SDK 不可用时页面不崩溃，也不显示虚假成功。
10. 原生 Codex Scheduled Tasks 不会被误标为工作台可管理任务。

## 15. 后续扩展边界

未来模块通过独立适配器和数据表接入：

- API 管理负责接口目录、用途、健康状态和凭证引用，不把密钥混入任务表。
- 商务对接负责联系人、合作事项和跟进记录。
- 经验复盘负责事件、结论、经验和后续行动。

如果未来支持云端或手机，必须增加本地代理、身份认证、传输加密和远程授权设计，不能直接将当前本地服务暴露到公网。
