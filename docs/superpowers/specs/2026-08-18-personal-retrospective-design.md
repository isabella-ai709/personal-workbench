# 个人经验复盘设计规格

- 日期：2026-08-18
- 状态：设计已确认，等待书面规格复核
- 本期范围：个人经验复盘的记录、查看、编辑与删除
- 后续范围：由用户主动触发的 AI 整理、经验提炼与改进建议

## 1. 背景与目标

Personal Workbench 是仅供用户本人使用的本机工作台。经验复盘模块用于快速记录日常事件中的做法、得失、经验和下一次行动，不引入团队协作、审批或权限管理。

核心原则是先形成持续使用习惯，再依据真实需求扩展。用户应能在 3～5 分钟内完成并保存一次复盘。

核心闭环为：

`回顾事情 → 分辨做对与做错 → 总结经验 → 明确下次改进 → 保存并在以后回看`

## 2. 设计原则

### 2.1 低门槛优先

首版采用单页输入，不使用向导、模板选择或多步骤跳转。只有复盘主题必填，其余内容可以留空，以免表单约束妨碍记录。

### 2.2 原始思考属于用户

用户填写的内容是正式原始记录。未来 AI 只生成辅助草稿，不直接覆盖原文；用户确认后才可采用 AI 建议。

### 2.3 本机优先

所有首版数据保存在工作台现有的本机 SQLite 数据库中，不发送给外部服务。未来只有用户主动点击 AI 辅助时，当前复盘内容才可提交给已配置的 AI 服务。

### 2.4 以真实使用决定扩展

首版不加入搜索、标签、统计、提醒、日历、自动草稿和 AI。功能扩展以实际复盘记录和使用障碍为依据。

## 3. 本期范围与非目标

### 3.1 本期包含

- 在工作台侧边栏增加“经验复盘”入口。
- 新建并保存个人复盘。
- 按创建时间倒序查看历史复盘。
- 查看和编辑已有复盘。
- 二次确认后软删除复盘。
- 对加载、校验和保存失败提供明确反馈。
- 离开未保存内容前提醒用户。

### 3.2 本期不包含

- 登录、多人使用、共享、评论、审批和权限管理。
- 标签、分类、关键词搜索和日历视图。
- 数据统计、连续打卡、提醒和目标管理。
- 自动保存草稿、模板库和逐步填写向导。
- AI 整理、润色、分析或建议。
- 回收站和用户可见的恢复操作。

软删除数据仍保留在数据库中，为以后增加恢复能力留下空间，但本期不提供恢复界面。

## 4. 页面与交互

经验复盘是一个独立页面，由历史区和内容区组成。历史区按创建时间倒序显示主题和创建时间；内容区显示当前复盘的详情或编辑表单。

新建复盘时，内容区一次展示全部字段：

1. 复盘主题。
2. 事情回顾。
3. 做对。
4. 做错。
5. 经验总结。
6. 下次改进。

“做对”和“做错”在视觉上属于同一个“做对 / 做错”阶段，但使用两个独立输入框，便于表达和未来 AI 分析。

主要交互规则：

- 点击“新建复盘”进入空白表单。
- 主题必填，其他字段允许为空。
- 保存期间禁用重复提交。
- 保存成功后进入该复盘的详情状态，并在历史列表顶部出现。
- 查看详情后可以进入编辑状态。
- 编辑旧复盘只更新修改时间，不改变其基于创建时间的历史位置。
- 删除前必须二次确认；删除成功后从历史列表隐藏。
- 页面存在未保存修改时，切换记录、新建、返回其他模块或关闭页面前应提示确认。
- 加载或写入失败时保留当前输入，并显示可理解的错误信息。

## 5. 数据模型

新增 `retrospectives` 表：

| 字段 | 类型与规则 | 用途 |
| --- | --- | --- |
| `id` | TEXT，UUID，主键 | 复盘唯一标识 |
| `title` | TEXT，1～200 字符，必填 | 复盘主题 |
| `review` | TEXT，最多 20,000 字符 | 事情回顾 |
| `did_well` | TEXT，最多 20,000 字符 | 做对的部分 |
| `did_wrong` | TEXT，最多 20,000 字符 | 做错的部分 |
| `lesson` | TEXT，最多 20,000 字符 | 经验总结 |
| `next_improvement` | TEXT，最多 20,000 字符 | 下次改进 |
| `created_at` | TEXT，ISO 时间，必填 | 创建时间 |
| `updated_at` | TEXT，ISO 时间，必填 | 最近修改时间 |
| `deleted_at` | TEXT，可空 | 软删除时间 |

为未删除记录建立按 `created_at DESC, id DESC` 排序的索引。相同创建时间时使用 `id` 保证稳定排序。

本期不在正式记录中加入 AI 字段。未来 AI 结果使用独立草稿表保存，以免把生成内容与用户原始内容混在一起。

## 6. 技术结构与数据流

模块沿用现有 React、Fluent UI、React Query、Fastify、Zod 和 SQLite 架构，并按职责拆分为：

- 共享契约：定义复盘实体、新建输入、更新输入和列表响应的 Zod schema 与 TypeScript 类型。
- Repository：负责 SQLite 查询、写入、软删除与行到领域对象的映射。
- Service：负责实体存在性检查、时间生成和领域操作。
- Routes：负责参数、请求体校验和 HTTP 状态码。
- API Client：封装浏览器端复盘请求。
- Page：组织历史列表、详情、表单、删除确认和错误反馈。

HTTP API 使用现有 `/api` 前缀：

```text
GET    /api/retrospectives
POST   /api/retrospectives
GET    /api/retrospectives/:id
PATCH  /api/retrospectives/:id
DELETE /api/retrospectives/:id
```

列表接口只返回未删除记录，并按创建时间倒序返回。新建返回 `201` 和完整实体；更新与删除操作必须先确认目标存在且未删除。删除接口执行软删除，不物理移除数据。

前端通过独立的 `retrospectives` 查询键管理缓存。新建、更新或删除成功后使列表查询失效并重新获取；详情可以使用服务端返回的完整实体直接更新缓存，避免无意义的重复请求。

## 7. AI 扩展边界

后期 AI 能力作为独立增强功能接入，首选能力包括：

- 整理表达：让已有内容更清晰，但不改变事实。
- 提炼经验：从回顾、做对和做错中形成候选经验。
- 生成改进建议：提出具体、可执行的下一次行动。

AI 扩展遵循：

1. 由用户主动触发，手动复盘始终可独立使用。
2. AI 请求读取当前复盘快照，不直接修改正式记录。
3. 生成结果保存为独立草稿，并标记来源复盘及生成时间。
4. 用户可以逐项查看、编辑、接受或放弃建议。
5. 只有用户确认后，建议才可以写入指定正式字段。
6. AI 调用失败不影响原始复盘的保存、查看和编辑。

## 8. 校验与错误处理

- 前后端都校验主题非空和所有字段长度；服务端校验是最终边界。
- 空主题和超长内容返回稳定的输入错误，不写入数据库。
- UUID 无效、记录不存在或已删除时返回明确的未找到错误。
- 保存和删除失败时不提前修改界面为成功状态。
- 删除必须由确认对话框触发，避免误触。
- 写请求沿用现有本机会话、Origin 和 Content-Type 安全校验。
- 时间由服务端生成，客户端不决定创建与更新时间。
- 本期没有并发编辑场景，不引入版本锁；未来出现跨窗口覆盖问题时再增加乐观并发控制。

## 9. 测试策略

### 9.1 单元测试

- 新建与更新输入 schema 接受有效内容。
- 空主题、超长内容和空更新被拒绝。
- 数据库行正确映射为领域对象。

### 9.2 集成测试

- migration 可重复执行，表和索引正确创建。
- 新建完整复盘和仅含主题的复盘。
- 列表只返回未删除记录，并稳定按创建时间倒序排列。
- 获取、编辑和软删除已有复盘。
- 无效 UUID、记录不存在、已删除记录和非法输入返回正确错误。
- 页面刷新后已保存数据仍然存在。
- 写请求继续受现有本地安全校验保护。

### 9.3 组件测试

- 首次进入时显示历史列表和新建入口。
- 单页表单展示全部字段并提交正确数据。
- 保存期间禁止重复提交，成功后刷新历史列表。
- 编辑旧记录不改变基于创建时间的列表位置。
- 删除前显示确认，删除后从列表消失。
- 请求失败时显示错误且不清空输入。
- 存在未保存修改时，切换上下文会触发离开确认。

## 10. 验收标准

1. 用户可以从工作台侧边栏进入经验复盘模块。
2. 用户可以在一个页面内填写主题和五个复盘内容字段。
3. 用户可以只填写主题并保存，也可以完整填写后保存。
4. 一次正常复盘可以在 3～5 分钟内完成。
5. 保存后的记录在刷新页面后仍然存在。
6. 历史列表按创建时间倒序展示，编辑不会改变该顺序。
7. 用户可以查看、编辑并二次确认后删除记录。
8. 校验或网络请求失败不会清空尚未保存的输入。
9. 首版在没有 AI 服务时功能完整可用。
10. 数据结构和模块边界允许后期增加独立 AI 草稿，而无需改写原始复盘模型。
