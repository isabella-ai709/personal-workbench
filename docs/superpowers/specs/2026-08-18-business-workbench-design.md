# 统一商务工作台设计规格

- 日期：2026-08-18
- 状态：设计已口头确认，等待书面规格复核
- 本期范围：商务资源、销售机会、合作项目、商务活动、跟进事项与 AI 辅助整理
- 后续范围：微信、邮箱、日历等外部渠道同步

## 1. 背景与目标

Personal Workbench 已具备任务日志和 Skill 管理。商务对接模块将在同一个本机工作台中管理公司、联系人、销售机会、合作项目、沟通历史和后续行动。

本期采用“统一商务工作台”模型：公司与联系人是共享资源，销售机会和合作项目是两类独立业务对象，商务活动和跟进事项是公共能力。系统既要支持销售成交，也要支持渠道合作、联合活动、供应商合作和资源互换等非纯销售场景。

本期目标是：

1. 建立公司和联系人的统一商务资源库。
2. 分别管理销售机会与合作项目，并形成可追溯的业务进展。
3. 用统一时间线沉淀沟通记录、关键事实和后续行动。
4. 集中查看到期、逾期和未来跟进事项。
5. 允许用户粘贴聊天或会议内容，由 AI 生成结构化草稿，经用户确认后写入正式数据。
6. 为外部渠道导入保留稳定边界，但本期不连接任何外部渠道。

核心闭环为：

`公司/联系人 → 销售机会或合作项目 → 商务活动 → 跟进事项 → 成交、完成或沉淀结果`

## 2. 设计原则

### 2.1 共享资源，分开业务

公司和联系人由销售机会与合作项目共享。销售机会与合作项目保持独立状态机和字段，不把所有商务行为强行塞进销售漏斗。

### 2.2 时间线是统一事实入口

电话、拜访、会议、微信沟通、邮件和普通备注都记录为商务活动。活动可以同时关联公司、联系人、销售机会与合作项目，并出现在各对象的时间线中。

### 2.3 AI 只生成草稿

AI 不直接修改正式数据，不自动推进业务阶段，不自动发送消息，也不把推测标记为已确认事实。所有提取结果必须经过用户预览、修改和确认。

### 2.4 本机优先并允许降级

模块沿用现有仅本机访问、安全会话和 SQLite 架构。AI 能力不可用时，手动录入、查询、推进和跟进仍能正常工作。

### 2.5 删除可恢复

公司、联系人及业务对象默认软删除。删除不得破坏历史活动、跟进和关联关系；存在活跃业务时限制删除公司，并给出明确处理指引。

## 3. 范围与非目标

### 3.1 本期包含

- 公司和联系人管理、搜索、筛选、标签与疑似重复提示。
- 销售机会的建立、阶段推进、成交和流失记录。
- 合作项目的建立、状态推进、关键节点和结果记录。
- 统一商务活动时间线。
- 跟进事项的创建、完成、延期和筛选。
- 商务总览和真实数据统计。
- AI 内容提取、草稿预览和确认写入。
- 外部导入适配层的数据边界。

### 3.2 本期不包含

- 微信、邮箱、日历、通讯录或其他第三方渠道的实际连接。
- 自动发送消息、自动外呼或自动跟进。
- 合同审批、电子签署、收付款、开票和财务核算。
- 复杂项目管理、甘特图、任务依赖和工时管理。
- 多用户协作、组织权限、客户公海和业绩分配。
- 自动合并重复公司或联系人。
- 基于预计金额生成正式收入或财务预测。

## 4. 领域模型

### 4.1 公司

公司代表客户、合作方、渠道、供应商或其他组织主体。

主要字段：

- 名称、简称、行业、地区、规模、官网和地址。
- 来源、标签和关系状态。
- 负责人、最近联系时间、下次跟进时间和备注。
- 创建、修改、软删除时间。

关系状态为：`潜在线索、接洽中、合作中、历史合作、暂不跟进`。

### 4.2 联系人

联系人可以归属于公司，也可以作为独立个人存在，后续再关联公司。

主要字段：

- 姓名、所属公司、职位和部门。
- 手机、微信、邮箱和其他联系方式。
- 决策角色、关系程度、沟通偏好、标签和备注。
- 最近联系时间、下次跟进时间。
- 创建、修改、软删除时间。

决策角色为：`决策者、影响者、使用者、执行者、未知`。联系方式不设强制唯一约束；系统提供疑似重复提示，由用户决定是否处理，不自动覆盖或合并。

### 4.3 销售机会

销售机会表示有明确或潜在成交目标的业务机会。

主要字段：

- 名称、关联公司和主要联系人。
- 当前阶段、需求摘要、产品或服务。
- 预计金额、币种、成交概率和预计成交日期。
- 来源、竞争情况、风险、负责人。
- 结果摘要、流失原因和阶段更新时间。

状态机为：

`线索 → 已接洽 → 需求确认 → 方案/报价 → 谈判 → 成交 / 流失`

允许向前推进，也允许退回非终态阶段并记录原因。进入“成交”或“流失”时必须填写结果摘要；进入“流失”时还必须填写流失原因。终态重新开启时必须记录原因。

### 4.4 合作项目

合作项目表示渠道合作、联合活动、供应商合作、资源互换等非纯销售业务。

主要字段：

- 名称、合作类型、目标、参与公司和联系人。
- 当前状态、开始日期和目标完成日期。
- 合作方案摘要、双方投入和预期产出。
- 关键节点、风险、结果摘要和负责人。

状态机为：

`构想 → 接洽中 → 方案确认 → 执行中 → 已完成 / 已终止 / 暂停`

“暂停”可以恢复到原非终态阶段；进入“已完成”或“已终止”时必须填写结果摘要。销售机会和合作项目可以互相关联，但互不继承状态。

### 4.5 商务活动

商务活动统一承载电话、拜访、会议、微信沟通、邮件和普通备注。

主要字段：

- 活动类型、发生时间、参与人。
- 原始内容、结构化摘要和内容来源。
- 关联公司、联系人、销售机会与合作项目。
- 创建方式：手动、AI 草稿确认或未来外部导入。
- 创建、修改时间。

一条活动至少关联一个公司、联系人、销售机会或合作项目。原始内容允许为空；用户可选择只保存摘要、不保留粘贴的原文。

### 4.6 跟进事项

跟进事项表示一次明确的后续行动。

主要字段：

- 标题、说明、截止时间、优先级和负责人。
- 状态、完成时间和完成说明。
- 来源商务活动。
- 关联公司、联系人、销售机会或合作项目。

状态为：`待处理、已完成、已取消`。延期不创建新事项，而是更新截止时间并保存变更记录。逾期是由截止时间计算出的展示状态，不是独立持久化状态。

### 4.7 负责人

第一版仍为单人工作台。负责人保存为可显示文本，默认使用本机工作台用户名称；该字段只用于筛选和未来迁移，不在本期引入用户、团队或权限表。

## 5. 页面和使用流程

### 5.1 商务总览

商务总览显示：

- 今日到期、已逾期和未来 7 天跟进事项。
- 销售机会数量、预计金额和阶段分布。
- 进行中的合作项目和近期关键节点。
- 最近新增或长期未联系的公司与联系人。
- 最近商务活动。
- 新增联系人、新增机会、新增合作和 AI 整理等快捷入口。

统计由服务端聚合真实数据。页面不展示没有明确数据来源或决策价值的装饰图表。

### 5.2 公司与联系人

公司列表支持关键词、标签、行业、地区、关系状态和最近联系时间筛选。公司详情聚合基本资料、联系人、销售机会、合作项目、统一时间线和未完成跟进。

联系人列表支持关键词、公司、决策角色、标签和最近联系时间筛选。联系人详情展示个人资料、所属公司、关联业务、时间线和待跟进事项。

### 5.3 销售机会

销售机会提供列表与阶段看板。用户可以创建机会、修改资料、推进或退回阶段、标记成交或流失，并查看相关活动和跟进。看板上的阶段移动仍需通过服务端状态校验。

### 5.4 合作项目

合作项目提供列表和详情视图。详情集中展示合作目标、参与方、关键联系人、当前状态、关键节点、沟通历史、风险和下一步行动。

### 5.5 跟进中心

跟进中心统一汇总所有业务对象产生的事项，支持今日、逾期、未来 7 天、已完成，以及优先级、对象类型和标签筛选。用户可以快速完成、延期、取消事项，或返回完整业务上下文。

### 5.6 新增商务活动与 AI 整理

AI 能力嵌入“新增商务活动”，不单独建设聊天页面。用户粘贴聊天记录、会议纪要或拜访笔记后，系统生成结构化草稿。用户逐项选择、修改关联对象和保存内容，确认后一次性写入活动，并按勾选项创建或更新业务对象与跟进事项。

## 6. AI 草稿设计

AI 输出使用受约束的结构化契约，包含：

- 沟通摘要。
- 客户需求和关注点。
- 已确认事实与双方承诺。
- 风险、异议和待确认问题。
- 建议的下一步行动及日期。
- 可能涉及的公司、联系人、销售机会或合作项目。

每个提取项标记为“原文事实”或“AI 建议”。无法从原文确认的信息保持为空或标记为待确认，不允许补造公司、人物、金额或日期。

草稿确认遵循以下规则：

1. 生成草稿不会修改正式业务表。
2. 用户可选择只保存摘要而不保存原始内容。
3. 用户逐项确认需要创建或更新的对象。
4. 确认操作在单个数据库事务中完成。
5. 确认请求使用幂等键，重复提交不会生成重复活动或跟进。
6. 草稿确认失败时保留草稿和用户修改，允许修正后重试。
7. AI 不可用时隐藏或禁用整理入口，手动新增活动仍可使用。

原始内容和 AI 输出在持久化前使用现有脱敏能力处理常见 API key、Bearer token 和敏感环境变量值。界面提示用户不要粘贴密码、密钥或无关敏感信息。

## 7. 技术架构与接口边界

后端沿用 Fastify、Zod 和 SQLite，在现有服务中增加独立 `business` 领域模块。浏览器只使用业务 ID，不提交本地路径或数据库标识细节。

建议按职责拆分为：

- 公司与联系人 repository/service/routes。
- 销售机会 repository/service/routes。
- 合作项目 repository/service/routes。
- 商务活动与时间线 repository/service/routes。
- 跟进事项 repository/service/routes。
- 商务总览聚合 service/routes。
- AI 草稿生成、保存与确认 service/routes。
- 外部导入标准化适配边界。

HTTP API 采用现有 `/api` 前缀，资源路由包括：

```text
/api/business/dashboard
/api/business/companies
/api/business/contacts
/api/business/opportunities
/api/business/partnerships
/api/business/activities
/api/business/follow-ups
/api/business/ai-drafts
```

写请求继续使用现有本机会话令牌、Origin、Content-Type 和 Zod 校验。列表接口统一支持分页、搜索、筛选和稳定排序。

### 7.1 外部渠道预留

未来渠道接入遵循：

`外部来源 → 原始导入记录 → 标准化商务活动草稿 → 用户确认 → 正式业务数据`

标准化记录保留 `source_type`、`external_id`、外部发生时间和安全的来源元数据。正式领域表不依赖某个渠道的专用字段。本期只定义适配接口和必要字段，不实现连接器、同步任务或授权流程。

## 8. 数据一致性与错误处理

- 新建公司或联系人时检查疑似重复，只提示，不阻止用户继续保存。
- 公司存在活跃销售机会或合作项目时禁止删除，并列出需要先处理的关联业务。
- 软删除对象默认不出现在列表和搜索中；恢复时重新检查名称和关键关联冲突。
- 状态更新由服务端校验合法转换，前端看板拖动不能绕过规则。
- 阶段变化、截止时间变化和终态重开记录变更时间、原因及前后值。
- AI 草稿确认、批量关联和同时创建跟进均使用事务，失败时不产生半完成数据。
- 重复确认和关键创建请求使用幂等键。
- 删除、状态冲突、对象不存在、输入错误和 AI 不可用使用稳定错误码及中文可读说明。
- 金额由数值和币种组成；预计金额只用于业务判断，不作为正式收入。
- 最近联系时间从已确认的商务活动中计算，不由 AI 草稿直接改写。

## 9. 测试策略

### 9.1 单元测试

- 销售机会和合作项目状态转换。
- 逾期与未来 7 天计算。
- 疑似重复匹配规则。
- AI 结构化输出校验、事实与建议分类。
- 金额、日期、终态原因和对象关联校验。

### 9.2 集成测试

- migration 可重复执行，外键和软删除行为正确。
- 公司、联系人、机会、合作、活动和跟进 API 生命周期。
- 同一活动在多个相关对象时间线中可见且不重复存储。
- AI 草稿生成不修改正式数据。
- AI 草稿确认的事务、幂等和失败恢复。
- 活跃业务删除限制、恢复冲突和本地安全校验。
- 商务总览聚合结果与底层数据一致。

### 9.3 组件与端到端测试

- 公司与联系人搜索、筛选和详情聚合。
- 销售机会看板和合法阶段推进。
- 合作项目状态与详情流程。
- 跟进事项完成、延期、取消和上下文跳转。
- 粘贴内容、编辑 AI 草稿、确认写入和重试。
- AI 服务不可用时的手动管理降级体验。

## 10. 验收标准

1. 用户可以建立公司、联系人及其关联关系。
2. 用户可以创建并推进销售机会和合作项目。
3. 一次沟通可以关联多个业务对象，并在相应时间线中同时看到。
4. 用户可以创建、完成、延期、取消和筛选跟进事项。
5. 用户可以粘贴沟通内容，经 AI 生成草稿，修改并确认写入。
6. 未确认的 AI 结果不会修改正式数据。
7. 删除、恢复、疑似重复和关联限制符合本规格。
8. 商务总览统计与底层业务数据一致。
9. AI 服务不可用时，手动商务管理不受影响。
10. 自动测试覆盖数据关系、状态转换、事务、幂等、安全校验、API 和主要页面交互。

## 11. 后续阶段

本期交付稳定后，再单独设计外部渠道接入。后续优先级根据实际使用决定，候选范围包括邮箱、日历、通讯录和微信材料导入。每个渠道都必须经过独立的授权、安全、去重和同步冲突设计，不能因本规格的接口预留而默认获得实施授权。
