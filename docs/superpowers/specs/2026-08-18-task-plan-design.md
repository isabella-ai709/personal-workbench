# 个人任务计划模块设计规格

- 日期：2026-08-18
- 状态：设计已确认，等待书面规格复核
- 范围：用个人任务计划替换现有任务日志与自动任务能力

## 1. 背景与目标

当前“任务日志”围绕 Cron 调度、Codex 自动执行和运行记录设计，无法自然承载用户的个人待办、计划和想法。新模块改名为“任务计划”，作为个人事项的统一记录与跟进入口。

模块帮助用户快速回答：

1. 今天应该优先处理什么？
2. 哪些事项已经超过原定计划时间？
3. 哪些事项正在进行或等待外部条件？
4. 最近记录了哪些尚未决定执行的想法？

## 2. 已确认的产品边界

### 2.1 任务计划是个人事项池

任务计划包含三种类型：

- `todo`（待办）：已经明确需要处理的事项。
- `plan`（计划）：准备推进、通常需要排期的事项。
- `idea`（想法）：先记录，尚未决定是否执行的事项。

第一版使用扁平条目，不支持子任务、任务树或步骤拆分。

### 2.2 与商务模块保持独立

商务模块现有跟进事项用于管理已经进入实际推进阶段的客户、联系人、商机和合作项目行动。任务计划不迁移、不替代、不自动同步这些商务跟进事项，也不直接关联商务对象。

任务计划与商务跟进之间存在概念上的前后关系，但第一版不实现转换功能。未来若增加“转为商务跟进事项”，应采用一次性转入并保留来源标识的方式，不建立双向状态同步。

### 2.3 自动任务完整移除

现有自动任务不是新模块的一部分。实施时删除：

- 任务日志页面、自动任务表单、运行详情和相关前端接口。
- 服务端任务调度器、Codex 自动任务执行适配器、自动任务接口及服务。
- 自动任务与运行记录数据库表及其中数据。
- 首页中的自动运行、成功、失败、暂停和运行记录指标。
- README 和其他当前功能说明中的任务日志描述。

现有自动任务及运行记录不迁移、不导出、不保留，数据库迁移完成后不可通过应用恢复。

## 3. 非目标

第一版不包含：

- 子任务、清单步骤或任务依赖。
- 自动提醒、消息通知或定时执行。
- Cron、Codex 自动运行或运行日志。
- 商务对象关联、商务跟进同步或转入操作。
- 看板、日历视图或多人协作。
- 重复任务、标签体系或自定义字段。

## 4. 任务计划模型

每条任务计划包含：

- `id`：UUID。
- `type`：`todo | plan | idea`。
- `title`：必填，去除首尾空白后长度为 1 至 300 个字符。
- `status`：`pending | in_progress | blocked | completed`。
- `priority`：`low | medium | high`。
- `dueAt`：可选、带时区的时间。未填写时为 `null`。
- `nextAction`：可选的下一步行动说明，最多 2,000 个字符。
- `notes`：可选备注，最多 20,000 个字符。
- `completedAt`：完成时间；仅完成状态有值。
- `createdAt`、`updatedAt`：创建与更新时间。
- `deletedAt`：软删除时间。

默认值为：类型 `todo`、状态 `pending`、优先级 `medium`，其余可选字段为空。

状态显示名称为：

- `pending`：待处理。
- `in_progress`：进行中。
- `blocked`：等待/受阻。
- `completed`：已完成。

状态切换规则：

- 未完成状态之间可以相互切换。
- 切换为已完成时写入 `completedAt`。
- 从已完成恢复时回到待处理，并清空 `completedAt`。
- 删除不改变原状态；恢复后回到删除前状态。

## 5. 页面信息架构

页面沿用“左侧列表 + 右侧详情”结构。

### 5.1 顶部视图

- 聚焦：默认视图，只显示需要执行的待办和计划。
- 全部：显示所有未删除、未完成事项，支持统一整理。
- 想法：集中显示未删除的想法。
- 已完成：显示完成事项，并支持恢复。
- 最近删除：显示软删除事项，并支持恢复。

搜索覆盖标题、下一步行动和备注。类型、状态和优先级可作为附加筛选条件。

### 5.2 聚焦分组

聚焦视图排除 `idea` 和 `completed`，每条事项只进入一个分组。分组按以下优先顺序判定：

1. **计划时间已过**：`dueAt` 的本地日期早于今天。
2. **今天处理**：`dueAt` 的本地日期为今天。
3. **等待/受阻**：状态为 `blocked`，且未进入前两个分组。
4. **未来 7 天**：截止日期在明天至未来第七天内。
5. **以后处理或未排期**：其他事项，默认折叠。

“计划时间已过”只是页面分组，不是任务状态。日期边界按 `Asia/Shanghai` 计算。

### 5.3 列表项

每条列表项显示：

- 标题。
- 类型。
- 状态。
- 优先级。
- 截止时间。
- 下一步行动摘要。

列表支持直接标记完成和切换状态。点击列表项后在右侧显示完整详情。操作提交期间禁用重复点击。

### 5.4 详情与编辑

右侧详情提供以下操作：

- 开始处理。
- 标记为等待/受阻。
- 标记完成。
- 恢复为待处理。
- 编辑。
- 删除。

创建与编辑表单包含类型、标题、状态、优先级、截止时间、下一步行动和备注。想法默认不要求截止时间；将想法的类型改为待办或计划后，它才可能进入聚焦列表。

## 6. 首页调整

首页删除所有自动任务运行指标，改为展示：

- 计划时间已过事项数。
- 今天处理事项数。
- 进行中事项数。
- 等待/受阻事项数。
- 最近记录的想法。

首页统计与任务计划使用同一服务和分组规则，避免首页与列表出现口径差异。

## 7. 技术边界

任务计划采用独立的共享契约、数据库迁移、Repository、Service、HTTP 路由、客户端 API 和页面组件。服务端负责输入校验、状态转换、软删除与日期查询；客户端只负责展示和发起明确操作。

建议使用独立的 `/api/task-plans` 接口，避免继续沿用带有自动执行语义的旧 `/api/tasks`。前端页面路径可以继续使用 `/tasks`，但页面标题、导航和可见文案统一为“任务计划”。

商务跟进表和接口不修改。删除自动任务表时不得影响商务跟进、商务活动或复盘数据。

## 8. 数据处理与删除

- 新任务计划列表初始为空。
- 自动任务和运行记录通过数据库迁移删除，不转换为任务计划。
- 任务计划使用软删除；最近删除中的事项可恢复。
- 第一版不做自动永久清理，避免引入额外保留策略和后台任务。

## 9. 异常处理

- 标题为空、字段超长或枚举值非法时，服务端拒绝保存并返回可读错误。
- 状态更新失败时，客户端保留原状态，不显示虚假成功。
- 创建、更新、完成、删除和恢复期间防止重复提交。
- 请求失败时保留当前列表与详情，并展示错误信息。
- 被编辑的事项已被删除时，服务端返回明确的不存在或已删除错误。
- 日期分组只依赖明确保存的 `dueAt`；无日期事项不得被误判为“计划时间已过”。

## 10. 测试策略

### 10.1 单元测试

- 创建与更新输入校验。
- 状态切换及 `completedAt` 写入和清除。
- 五个聚焦分组的边界与唯一归组。
- `Asia/Shanghai` 的跨日边界。
- 软删除和恢复。

### 10.2 集成测试

- Repository 的创建、读取、更新、完成、删除和恢复。
- HTTP 接口的成功、校验失败和不存在响应。
- 数据库升级后自动任务表被移除，商务与复盘数据仍然存在。
- 首页统计与任务计划列表口径一致。

### 10.3 页面测试

- 创建待办、计划和想法。
- 聚焦视图的分组、排序与折叠。
- 想法不会出现在聚焦视图，改为待办或计划后可以出现。
- 列表快捷切换状态和标记完成。
- 已完成事项恢复。
- 删除与最近删除恢复。
- 刷新页面和重启服务后数据保持一致。

## 11. 验收标准

1. 导航、页面标题和当前功能说明统一使用“任务计划”。
2. 可以新增、编辑、搜索、筛选、完成、恢复和删除个人事项。
3. 支持待办、计划、想法三种类型和四种已确认状态。
4. 聚焦视图按照“计划时间已过、今天处理、等待/受阻、未来 7 天、以后处理或未排期”唯一分组。
5. 想法默认不进入聚焦视图，已完成事项不混入当前工作列表。
6. 首页展示个人任务概览和最近想法，且统计口径与列表一致。
7. 商务模块及其跟进事项行为和数据不受影响。
8. 项目中不再存在可访问或运行的自动任务功能。
9. 自动任务数据库表删除后，其他业务数据仍可正常读取。
10. 刷新页面或重启服务后，任务计划数据和状态保持一致。
